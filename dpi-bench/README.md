# dpi-bench — стенд «как нас видит ТСПУ»

Набор скриптов, который снимает трафик KS, CITP, WireGuard, OpenVPN и обычного HTTPS
при одинаковой нагрузке и прогоняет его через детекторы, повторяющие публично
описанные методы российского ТСПУ. Цель — не «доказать неуловимость», а честно
показать, где протоколы Chameleon заметны, а где нет, и что чинить в первую очередь.

> **Оговорка.** Это модель, а не настоящий ТСПУ. Правила реального оборудования
> закрыты и меняются; мы воспроизводим только то, что описано публично (источники
> ниже). Live-часть идёт по реальному пути РФ → зарубеж, но через канал дата-центра,
> а не через мобильного оператора, где фильтрация обычно жёстче.

## Что внутри

| Файл | Назначение |
|---|---|
| `lab.sh` | Лаборатория на netns: `dpc` (клиент) → `dpm` (цензор: tcpdump + nftables + netem 40 мс) → `dps` (сервер). Протоколы: `ks` (udp 51830), `citp`, `citp-cbr` (tcp 9443), `wg` (udp 51820), `ovpn` (TLS-режим, udp 1194), `tls` (443). Команды `up/down/capture/sessions/probe/policy/all`. |
| `workload.py` | Одинаковая нагрузка через туннель: фазы idle / web / chat / bulk, метки времени в `phases.json`. |
| `probe.py` | Активное зондирование сервера: случайные датаграммы 1..1200 Б, повтор/обрезка/битфлип настоящего пакета; для TCP — молчание, случайные 1/104/600 Б, HTTP, TLS ClientHello, повтор; замер времени до закрытия. |
| `analyze.py` | Детекторы D1–D8 → `report.json` / `report.md`. |
| `live.sh`, `live-node.sh` | Тот же замер по реальному пути: клиент на RU-ноде, сервер за рубежом, pcap с обеих сторон. |
| `compare.py` | Сравнение pcap клиента и сервера: потери вверх/вниз, внедрённые пакеты, максимальная пауза загрузки → `compare.md`. |
| `cmd/dpi-citp` | Минимальный CITP-клиент (`DialNode` + mux, проброс локального порта, `-cbr`). |

## Детекторы

| ID | Что ищет | Откуда метод |
|---|---|---|
| D1 | Сигнатуры первых пакетов: WireGuard (148 Б, тип 1), OpenVPN (0x38→0x40), TLS, QUIC, DTLS, STUN | классический DPI по протоколам, NTC |
| D2 | «Полностью зашифрованный» трафик (FET): popcount на байт 3.4–4.6, нет печатного префикса ≥6 Б, нет ≥50% печатных | Wu et al., USENIX Security 2023 (GFW) |
| D3 | Размеры/направления первых 5 пакетов сеанса и их повторяемость | The Insider: блокировка по первым пакетам |
| D4 | Пульс простоя: регулярные пакеты с CV интервалов < 0.15 | keepalive как отпечаток |
| D5 | ACK-эхо: доля пакетов вверх одного малого размера (TCP-ACK внутри туннеля) | анализ потоков внутри UDP-туннелей |
| D6 | Выравнивание длин (mod 16) по различным длинам | блочное шифрование/паддинг |
| D7 | Ответы на активные зонды и время закрытия | active probing (GFW, ТСПУ) |
| D8 | Политики цензора: UDP-блок, только порты < 1000, «заморозка» после 16 КБ, бан UDP на 10 мин | Habr: заморозка TCP после ~16 КБ к зарубежным адресам; sonicdpi |

## Запуск

```bash
# лаборатория (root, ~50 мин; результаты в $OUT, pcap не коммитим)
OUT=./results/run1 ./lab.sh all          # capture → sessions → probe → policy → analyze
python3 analyze.py ./results/run1        # повторный анализ

# live: клиент в РФ, сервер за рубежом
export OUT=./results/live1 RU_RUN=... FX_RUN=... FX_COPY=... RU_IP=... FX_IP=...
./live.sh prepare && ./live.sh start
./live.sh status      # ждать DONE
./live.sh collect && ./live.sh stop
python3 compare.py $OUT
```

Тестовые туннели используют свои интерфейсы и порты и не трогают боевые.

## Результаты (8 октября 2026)

Полные отчёты: [`docs/dpi/lab-report.md`](../docs/dpi/lab-report.md) (лаборатория),
[`docs/dpi/live-report.md`](../docs/dpi/live-report.md) и [`docs/dpi/live-compare.md`](../docs/dpi/live-compare.md)
(живой путь RU-нода → Azure eastus).

**Признаки, за которые может зацепиться DPI (лаборатория, из 7):**
KS — 2, CITP — 2, CITP + CBR — 1, WireGuard — 5, OpenVPN — 2, HTTPS — 0.

| | KS | CITP | WireGuard | OpenVPN |
|---|---|---|---|---|
| Сигнатура первого пакета | нет | нет | **есть** | **есть** |
| Ответ на активные зонды | молчит | молчит (порт открыт, закрытие через 15/45 с) | молчит | **отвечает** |
| Полностью зашифрован (FET) | **да** | **да** | да | нет |
| ACK-эхо внутри туннеля | **да (97% вверх = 108 Б)** | нет (TCP-прокси) | да | нет/да |
| Пульс простоя | нет (ks-vpn) | **каждые 5.0 с** (CBR его маскирует) | нет | нет |
| Работает при блоке UDP / бане за UDP | ❌ | ✅ | ❌ | ❌ |
| Заморозка после 16 КБ | ❌ | ❌ | ❌ | ⚠️ |
| Только порты < 1000 | ❌ (тест на высоких портах) | ❌ (9443) | ❌ | ❌ |

Живой путь: все шесть протоколов работают 56/56, вмешательства сети не видно
(лишние/потерянные пакеты укладываются в недописанное tcpdump, пауз загрузки > 0.14 с нет).
Скорость: KS 16, CITP 45, CITP + CBR 48, WireGuard 34, OpenVPN 19, HTTPS 49 Мбит/с.

**Выводы.** Сигнатурами KS и CITP не ловятся, на зонды не отвечают. Их уязвимое место —
поведенческие классы: «полностью зашифрованный» трафик (правило FET), ACK-эхо у KS
и ровный 5-секундный пульс у CITP. Политики по IP/объёму (заморозка после 16 КБ, белые
порты) от протокола не зависят — от них защищают только порт 443 и смена адресов.

## Beta: после исправлений (ветка CITP-and-KS-Beta)

Отчёт: [`docs/dpi/beta-lab-report.md`](../docs/dpi/beta-lab-report.md). Тот же стенд, KS с `-pad 200`,

| **Признаков из 7** | 2 | **1** | 2 | **0** | 1 | **0** |

| ACK-эхо | 🔴 97% = 108 Б | 🟢 паддинг | — | — | — | — |
| Пульс простоя | 🟢 | 🟢 | 🔴 ровно 5.0 с | 🟢 джиттер ±40% | 🟢 | 🟢 |
| Закрытие зонда | — | — | 15/45 с | 10–45 с случайно | 15/45 с | 10–45 с |
| Только порты < 1000 | ❌ | ❌ | ❌ | ✅ (853/443) | ❌ | ✅ |
| Скорость загрузки (лаб.) | 75 Мбит/с | 94 Мбит/с | 50 Мбит/с, обрывы потока | 133 Мбит/с, 56/56 | 95 Мбит/с | 132 Мбит/с |

KS: дрейф часов ±30 с → 99–100% доставки (было 0% при |дрейф| ≥ 9 с), см. `internal/chaossync/ks_skew_test.go`.
Оговорки: заголовок TLS-записи обманывает FET-эвристику, но полноценный TLS-парсер увидит мусор
после заголовка; заморозку после 16 КБ (freeze16k) по-прежнему не переживает ни один протокол.
Модель ≠ реальный ТСПУ: это воспроизведение опубликованных методов, а не доступ к оборудованию.
